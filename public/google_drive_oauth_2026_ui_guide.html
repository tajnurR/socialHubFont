Overview

Your application asks the user to provide Google OAuth details. That means the user must create a Google Cloud project, create an OAuth client, copy the Client ID and Client Secret, then paste those details into your application.

What the user creates in Google

  • Google Cloud Project
  • Enabled Google Drive API
  • OAuth App Branding
  • OAuth Web Client
  • Client ID and Client Secret

What the user enters in your app

  • Label
  • OAuth Client ID
  • OAuth Client Secret
  • Redirect URI
  • Scopes

Category 1: Create Google Cloud Project

  1. Open Google Cloud Console.
  2. Click the project selector at the top of the page.
  3. Click New Project.
  4. Enter a project name.
Example Project Name: My Drive Connection
  1. Click Create.
  2. Wait a few seconds, then make sure the new project is selected.

Category 2: Enable Google Drive API

This step allows the application to call Google Drive APIs for reading and writing files.

  1. Use the Google Cloud search bar.
  2. Search for Google Drive API.
  3. Open Google Drive API.
  4. Click Enable.
Important: If the Google Drive API is not enabled, your OAuth connection may succeed, but Drive read/write requests can fail later.

Category 3: Configure Google Auth Platform

Now configure the OAuth app identity. This is what users see on the Google consent screen.

3.1 Open Google Auth Platform

  1. From the left menu, open Google Auth Platform.
  2. Click Get started.

3.2 App Information

Fill in the basic application information.

Field What to Enter
App name Your application name, for example SocialHub
User support email Your email address
Logo Optional

Click Next.

3.3 Audience

Select who can use this OAuth app.

Option When to Use
External Use this when normal Gmail users or users outside your organization will connect their Google Drive.
Internal Use this only if the app is for users inside the same Google Workspace organization.

For most public applications, choose External. Then click Next.

3.4 Contact Information

  1. Enter your developer/contact email address.
  2. Click Next.
  3. Click Create.
After this step, the basic OAuth branding is created. Now the left menu items such as Data Access and Clients become usable.

Category 4: Add Google Drive Permission / Scope

The scope defines what your application is allowed to do with the user's Google Drive.

  1. Open Google Auth Platform.
  2. Click Data Access from the left menu.
  3. Click Add or remove scopes.
  4. Search for Drive.
  5. Select the scope your application needs.
  6. Click Save.

Recommended Scope

https://www.googleapis.com/auth/drive.file

This is the recommended scope for most apps because it allows the application to create, upload, update, and manage files that the user creates or selects with your app.

Other Possible Scopes

Scope Use Case
https://www.googleapis.com/auth/drive.file Best for most apps. Access files created or selected by your app.
https://www.googleapis.com/auth/drive.readonly Read files from the user's Drive but do not write/update files.
https://www.googleapis.com/auth/drive Full Drive read/write access. Use only if truly required.
Use the smallest scope possible. Full Drive access may require more review and may make users less comfortable granting permission.

Category 5: Create OAuth Client

  1. Open Google Auth Platform.
  2. Click Clients from the left menu.
  3. Click Create Client.
  4. Select Web application.
  5. Enter a client name.
Example Client Name: SocialHub Google Drive Client

5.1 Authorized JavaScript Origins

Add your frontend origin.

Environment Origin
Local Development http://localhost:4200
Production https://your-domain.com

5.2 Authorized Redirect URI

This must match your application's redirect URI exactly.

Environment Redirect URI
Local Development http://localhost:4200/settings/social-integrations/storage-drive
Production https://your-domain.com/settings/social-integrations/storage-drive
Must match exactly: The redirect URI in Google Cloud and the redirect URI in your application must be exactly the same. Protocol, domain, path, and trailing slash all matter.

Click Create.

Category 6: Copy Google Credentials

After creating the OAuth client, Google shows two important values:

  • Client ID
  • Client Secret
Client ID example: xxxxxxxxxxxx.apps.googleusercontent.com Client Secret example: GOCSPX-xxxxxxxxxxxxxxxx
Keep the Client Secret private. Do not expose it in frontend code, public repositories, screenshots, or logs.

Category 7: Fill Your Application Form

Return to your application and complete the Google OAuth credentials form.

Your App Field What to Enter
Label Any name for this connection, for example My Google Drive
OAuth Client ID Paste the Client ID from Google Cloud.
OAuth Client Secret Paste the Client Secret from Google Cloud.
Redirect URI Use the same redirect URI configured in Google Cloud.
Scopes Use https://www.googleapis.com/auth/drive.file unless your app needs broader access.

After entering all information, click Save Google config.

Category 8: Connect Google Drive

  1. After saving the Google config, click Connect Google Drive.
  2. Google opens the OAuth consent screen.
  3. Select the Google account you want to connect.
  4. Review the requested Drive permission.
  5. Click Allow.
  6. Google redirects back to your application.

Behind the scenes, Google sends an authorization code to your redirect URI. Your backend exchanges that code for an access token and refresh token. The access token is used to call Google Drive. The refresh token is used to get a new access token when the old one expires.

Category 9: Testing and Production Notes

Testing Mode

If the OAuth app is still in Testing mode, only added test users can connect. If another user tries to connect, they may see an access error.

  1. Go to Google Auth Platform.
  2. Open Audience.
  3. Add test user email addresses.

Production Mode

For real users, publish the OAuth app to production. Some sensitive or restricted scopes may require Google verification before public use.

If you use drive.file, your app generally follows the least-privilege approach and is easier to explain to users.

Common Errors and Solutions

Error Cause Solution
redirect_uri_mismatch The redirect URI in Google Cloud does not exactly match the one used by the application. Copy the redirect URI from your app and paste it exactly into Google Cloud.
invalid_client Wrong Client ID or Client Secret. Copy the credentials again from Google Auth Platform → Clients.
invalid_grant The authorization code was already used, expired, or the refresh token was revoked. Reconnect Google Drive from the beginning.
access_denied The user denied Google permission. Try again and click Allow.
Google Drive token expired or was revoked The stored refresh token is no longer valid. Remove old tokens and reconnect the Google Drive account.

Final Field Mapping for Your Application

Your App Field Where the User Gets It
Label User writes any name.
OAuth Client ID Google Auth Platform → Clients → OAuth Web Client.
OAuth Client Secret Google Auth Platform → Clients → OAuth Web Client.
